# microvpn Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A login-less web app that creates temporary WireGuard rooms and relays their encrypted UDP between members without ever holding a key, deployed as one rootless podman container under `https://raubcamaioni.com/microvpn/`.

**Architecture:** One FastAPI process: a JSON API and two server-rendered pages, a `RoomService` that owns rooms, members and pair ports in SQLite, and an asyncio UDP `Relay` with one datagram endpoint per member pair that forwards WireGuard packets between the two addresses it learns. Keys are generated on the member's device (browser or `wg genkey`); the server renders the config with a private-key placeholder that the client fills in.

**Tech Stack:** Python 3.12 (containers only), FastAPI, SQLModel/SQLite, Jinja2, asyncio datagram transports, uvicorn (uvloop in the image), vanilla JS with vendored tweetnacl and qrcode-generator, pytest, podman, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-22-microvpn-design.md`

## Global Constraints

- Python 3.12 is the only target. Nothing is installed on the Windows host: tests, the dev server and the image are built and run in containers from `containers/Containerfile` (stages `base`, `test`, `runtime`). Locally `./test.sh` and `./build.sh` run podman inside the WSL `Ubuntu` distro (26.04, podman 5.7, the same engine as the server); CI runs the same stages with docker.
- Datetimes are naive UTC everywhere (`utcnow()` from `app.models`); SQLite drops timezones.
- Every HTTP response carries `Cache-Control: no-store`.
- All URLs the pages emit start with `root_path` (`ROOT_PATH=/microvpn` in production, `""` in tests unless a test sets `root_path`).
- Defaults copied from the spec: `ROOM_MAX_MEMBERS=8`, `ROOM_MAX_LIVE=64`, `ROOM_CREATE_PER_IP_PER_HOUR=3`, `ROOM_MBPS=50`, `RELAY_TOTAL_MBPS=200`, `ROOM_LIFETIMES=1,4,12,24`, `RELAY_PORT_RANGE=20000-21999`, `HTTP_BIND=0.0.0.0:8080`.
- Names: room name 0 to 40 characters, device name 1 to 32 characters, both stripped, printable, no control characters. Room id: 26 lower-case base32 characters. Tokens: 22-character url-safe base64 of 16 random bytes. Public key: 44-character base64 decoding to 32 bytes.
- Config file name and interface tag: `mv` + first 8 characters of the room id.
- Private key placeholder in rendered configs: `__PRIVATE_KEY__`.
- Relay packet rules: length ≥ 32; type byte 1 to 4; bytes 1 to 3 zero; type 1 length 148, type 2 length 92, type 3 length 64, type 4 length ≥ 32.
- Line endings LF (`.gitattributes` is committed). Formatting: `ruff format` at 120 columns is the style; not enforced by CI.
- Commit messages end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- Nothing runs on the production host outside podman. The container has no capabilities and no host networking.

## Review Focus

- **A device name containing a newline or `[Peer]`** must not break the rendered config: names are rejected at join when they contain control characters (Task 2, Task 6), and the config comment line is a single line (Task 4).
- **A public key that is valid base64 but not 32 bytes, or carries whitespace,** returns 400, never 500 (Task 2 test `test_public_key_rejects_wrong_length_and_whitespace`).
- **Port exhaustion mid-join** (the pool runs dry while creating the 7th pair) must leave no half-joined member: the join rolls back, closes the ports it opened, and returns 503 (Task 6 test `test_join_rolls_back_when_ports_run_out`).
- **A room whose `expires_at` has passed but the sweeper has not run yet** must already be 404 on every endpoint (Task 6 test `test_expired_room_is_gone_before_sweep`).
- **Restart with a pair port that something else now holds** must not crash startup: `restore()` skips the port, logs it, and the app serves (Task 6 test `test_restore_skips_ports_that_fail_to_bind`).

- [ ] **Step 7: Implement `PairPort` and `Relay` in `app/relay.py`**

`PairPort(asyncio.DatagramProtocol)` holds `room_id`, two `Slot(addr, last_seen)` at most, the room and global buckets, the clock. `datagram_received(data, addr)`: `kind = packet_kind(data)`; drop on `None`; find the slot with `addr` → update `last_seen`; else if fewer than two slots → append; else if `kind in (1, 2)` → replace the slot with the smaller `last_seen`; else drop. Then the other slot, if any: `if room_bucket.take(len(data)) and global_bucket.take(len(data)): transport.sendto(data, other.addr)`. `Relay.open` uses `loop.create_datagram_endpoint(lambda: PairPort(...), local_addr=(settings.RELAY_BIND, port), reuse_port=False)` and returns `False` on `OSError`, logging at warning. `close` calls `transport.close()` and forgets the port; `close_room` closes every port of the room and drops its bucket. The 25-byte bucket arithmetic: `rate = mbps * 1e6 / 8`, `burst = rate`.
